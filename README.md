# Челлендж 6 месяцев — трекер

Личное веб-приложение (PWA) для ежедневного, еженедельного и ежемесячного трекинга денежного 6-месячного челленджа. Работает в Safari на iPhone, ставится на экран «Домой» как обычное приложение, работает офлайн. Личные данные (дни, недели, месяцы, эфиры, CRM, дневник) хранятся только на твоём телефоне (в браузере) — никуда не отправляются.

**Хостинг сейчас — GitHub Pages** (не Vercel). Изначально планировали перенести на Vercel ради серверной функции, которая прячет токен для автоматической части воронки (см. ниже), но уткнулись в верификацию телефона на стороне Vercel — вернёмся к переносу позже. Пока автоматическая часть воронки (статистика из бота) отключена и показывает заглушку «Подключим позже — ждём доступ к Vercel», ручная часть воронки (разборы → тест-драйв → флагман) работает уже сейчас.

## Как посмотреть изменения локально (на компьютере)

Программистом быть не обязательно.

1. Открой приложение «Терминал» на Mac.
2. Перейди в папку проекта:
   ```
   cd /Users/Freeman/chelendzh-app
   ```
3. Запусти простой локальный сервер (Python уже есть на Mac):
   ```
   python3 -m http.server 8000
   ```
4. Открой в браузере http://localhost:8000
5. Чтобы остановить сервер — вернись в Терминал и нажми `Control + C`.

## Как передеплоить после правок

Сайт живёт на GitHub Pages. Чтобы изменения появились по той же ссылке:

1. В Терминале перейди в папку проекта: `cd /Users/Freeman/chelendzh-app`
2. Сохрани изменения и отправь их на GitHub:
   ```
   git add -A
   git commit -m "Описание изменений"
   git push
   ```
3. Через 30–60 секунд GitHub Pages сам обновит сайт по той же ссылке.

Если правил самостоятельно и что-то не работает — попроси помочь через Claude Code в этой же папке, он видит всю историю проекта.

## Когда будет готов доступ к Vercel

В коде уже подготовлена серверная функция `api/funnel-proxy.js` для автоматической части воронки — она просто не используется, пока сайт на GitHub Pages (там нет серверных функций). Когда пройдёшь верификацию на Vercel, попроси Claude Code:
1. Перенести проект на Vercel (`npx vercel --prod`, привязать GitHub-репозиторий).
2. Установить секретный токен переменной окружения на Vercel (см. раздел ниже).
3. Включить флаг `FUNNEL_AUTO_ENABLED = true` в начале `js/app.js` — после этого экран «Воронка» начнёт подтягивать реальные данные из бота вместо заглушки.

## Структура проекта

- `index.html` — вся разметка экранов (Дашборд, Сегодня, Неделя, Месяц, Оплаты, Воронка, CRM, Эфир, Настройки)
- `css/style.css` — оформление (тёмная тема)
- `js/app.js` — вся логика: хранение данных, расчёты, переключение экранов
- `api/funnel-proxy.js` — серверная функция Vercel: прячет токен и проксирует запрос к статистике воронки
- `manifest.json`, `sw.js` — технические файлы PWA (установка на экран «Домой», офлайн-режим)
- `icons/` — иконки приложения

Стек: чистые HTML/CSS/JS без сборщиков и фреймворков — любой файл можно открыть и поправить напрямую. Единственная серверная часть — одна маленькая функция для проксирования токена.

## Переменная окружения (секретный токен) — понадобится при переезде на Vercel

Токен для чтения статистики воронки (`LESSON_STATS_TOKEN`) должен храниться **только** в настройках проекта на Vercel, не в коде и не в git. Когда дойдём до переноса:

```
vercel env add LESSON_STATS_TOKEN production
```

Терминал попросит ввести значение — вставь токен и нажми Enter. После этого нужно передеплоить (`npx vercel --prod`), чтобы функция подхватила новое значение.

Перед каждым пушем в git полезно проверить, что токен нигде не остался в файлах, например:
```
git grep -F "$LESSON_STATS_TOKEN"
```
(вставь реальное значение токена вместо переменной, если он не установлен в переменных окружения терминала). Пустой результат — значит всё чисто.

## Данные и приватность

Все записи (дни, недели, месяцы, эфиры, CRM-контакты, дневник) хранятся в `localStorage` браузера — только на этом устройстве. Бэкенда и базы данных для личных данных нет.

В «Настройках» есть:
- **Экспорт данных (JSON)** — сохранить резервную копию на телефон/компьютер;
- **Импорт данных** — восстановить из такого файла (например, при смене телефона);
- **Стереть все данные** — полная очистка (с двойным подтверждением).

Резервные копии стоит делать периодически вручную — автоматической синхронизации между устройствами нет (осознанное решение, см. ниже).

## Решения и допущения, которые я сделал сам

- **Месяц челленджа (1–6)** считается по календарным месяцам от даты старта.
- **«Сколько нужно продаж флагмана»** — целевой доход делится на чек флагмана, округляется вверх. Дальше приложение считает, сколько таких продаж уже сделано с начала челленджа и сколько в среднем нужно в оставшиеся месяцы.
- **«Потолок одновременных флагман-клиентов»** — пока справочное значение в настройках, на расчёты дашборда не влияет (в ТЗ нет точной формулы, как он должен их ограничивать).
- **Заявки задуманы как автоматические** (экран «Воронка», данные из бота через `/api/funnel-proxy`) — поле «Заявок пришло» убрано с экрана «Сегодня». Пока сайт на GitHub Pages, эта часть — заглушка «Подключим позже — ждём доступ к Vercel» (флаг `FUNNEL_AUTO_ENABLED = false` в начале `js/app.js`). Ручная часть воронки (разборы → тест-драйв → флагман) работает уже сейчас и не зависит от этого флага. На «Неделе» число заявок за неделю — это оценка по истории снимков воронки; пока авто-часть выключена, снимков не появляется, поэтому там будет «нет данных» — это ожидаемо.
- **Расходы на рекламу и стоимость лида убраны из экрана «Месяц»** — по этому промпту такая аналитика уже ведётся в воркботе и не должна дублироваться здесь.
- **Связь «Эфир» → воронка**: количество записавшихся на разбор с экрана «Эфир» по-прежнему автоматически добавляется в поле «Разборы/созвоны» дневного чек-листа за дату эфира.
- **Задания этапа 1** (дни 1–7 и 30) показываются на экране «Сегодня» под датой, которая сейчас открыта (а не обязательно под сегодняшней датой) — так подсказка совпадает с тем, что физически смотрит человек. Дни 1, 3, 4, 5 дают текстовое поле для короткой заметки; дни 2, 6 — просто текст-подсказка; дни 7 и 30 — текст со ссылкой на «Неделю»/«Месяц».
- **Оплаты** — отдельный экран с карточками клиентов (имя, формат продукта, общая сумма, список платежей). Сумма всех платежей за календарный месяц (по датам самих платежей) используется как «факт дохода месяца» на Дашборде и на экране «Месяц» — это заменило прежнюю логику прогресса «по числу проданных флагманов». Это отдельная сущность от счётчиков «продажа теста/флагмана» на экране «Сегодня»: те считают факт сделки (разбор закрылся продажей), «Оплаты» считают реальные деньги, которые фактически пришли — при рассрочке это разные по времени вещи.
- **CRM** — отдельный список контактов с этапами (старый / новый / переписка / назначен созвон / созвон проведён / внёс оплату), полностью локальный, никак не связан с воронкой лидов из п.7 промпта (это разные сущности: воронка — автоматические лиды из бота, CRM — ручная база, которую ведёт Максим сам).
- **Кеш воронки**: если запрос к `/api/funnel-proxy` не проходит (нет сети, сервер недоступен), экран «Воронка» показывает последние успешно загруженные числа из кеша с пометкой времени последнего обновления.
- **Автосохранение**: большинство полей сохраняются сразу при изменении, кнопки «Сохранить» — как явное подтверждение «записано».
- Файла `mehanika-chelendzha-v1.md` в папке по-прежнему нет — все формулировки взяты из текста промптов.

## Дизайн

Тёмная тема — единственная и постоянная, в духе матовой премиальной техники: графитовый фон с едва заметной текстурой, один акцентный цвет (тёмно-красный/бордовый) для кнопок и прогресса, всё остальное — оттенки серого и белого. Иконки — тонкие линейные, без заливки. Нижняя навигация и быстрые переходы на дашборде — 7 разделов: Главная, Сегодня, Неделя, Месяц, Воронка, CRM, Эфир.
