# Челлендж 6 месяцев — трекер

Личное веб-приложение (PWA) для ежедневного, еженедельного и ежемесячного трекинга денежного 6-месячного челленджа. Работает в Safari на iPhone, ставится на экран «Домой» как обычное приложение, работает офлайн. Все данные хранятся только на твоём телефоне (в браузере) — никуда не отправляются.

## Как посмотреть изменения локально (на компьютере)

Программистом быть не обязательно, но браузеры не дают открыть PWA просто двойным кликом по `index.html` (не заработает офлайн-режим и сохранение). Поэтому нужно поднять локальный сервер — это одна команда.

1. Открой приложение «Терминал» на Mac.
2. Перейди в папку проекта:
   ```
   cd /Users/Freeman/chelendzh-app
   ```
3. Запусти локальный сервер (в Mac уже есть Python, ничего ставить не надо):
   ```
   python3 -m http.server 8000
   ```
4. Открой в браузере: http://localhost:8000
5. Чтобы остановить сервер — вернись в Терминал и нажми `Control + C`.

## Как передеплоить после правок

Приложение живёт на GitHub Pages. Чтобы изменения появились по той же ссылке:

1. В Терминале перейди в папку проекта: `cd /Users/Freeman/chelendzh-app`
2. Сохрани изменения и отправь их на GitHub:
   ```
   git add -A
   git commit -m "Описание изменений"
   git push
   ```
3. Через 30–60 секунд GitHub Pages сам обновит сайт по той же ссылке — ничего больше делать не нужно.

Если правил самостоятельно и что-то не работает — попроси помочь через Claude Code в этой же папке, он видит всю историю проекта.

## Структура проекта

- `index.html` — вся разметка экранов (Дашборд, Сегодня, Неделя, Месяц, Эфир, Настройки)
- `css/style.css` — оформление (тёмная тема)
- `js/app.js` — вся логика: хранение данных, расчёты, переключение экранов
- `manifest.json`, `sw.js` — технические файлы PWA (установка на экран «Домой», офлайн-режим)
- `icons/` — иконки приложения

Стек: чистые HTML/CSS/JS, без сборщиков и фреймворков — любой файл можно открыть и поправить напрямую.

## Данные и приватность

Все записи (дни, недели, месяцы, эфиры, дневник) хранятся в `localStorage` браузера — только на этом устройстве. Бэкенда, серверной базы данных и авторизации нет и не предполагается.

В «Настройках» есть:
- **Экспорт данных (JSON)** — сохранить резервную копию на телефон/компьютер;
- **Импорт данных** — восстановить из такого файла (например, при смене телефона);
- **Стереть все данные** — полная очистка (с двойным подтверждением).

Резервные копии стоит делать периодически вручную — автоматической синхронизации между устройствами нет (это осознанное решение, см. ограничения ниже).

## Решения и допущения, которые я сделал сам

Часть формулировок в ТЗ можно было трактовать по-разному. Вот что я решил и почему:

- **Месяц челленджа (1–6)** считается по календарным месяцам от даты старта (месяц старта = месяц 1, следующий календарный месяц = месяц 2 и т.д.), а не по 30-дневным периодам.
- **«Сколько нужно продаж флагмана»** — я перевёл целевой доход в число флагман-клиентов простым делением: `целевой доход ÷ чек флагмана`, округлённое вверх. Это трактует цель как «набрать столько флагман-клиентов, сколько нужно для целевого месячного дохода», а не как отдельный ежемесячный план продаж. Дальше приложение считает, сколько таких продаж уже сделано с начала челленджа и сколько в среднем нужно в оставшиеся месяцы.
- **Поле «Потолок одновременных флагман-клиентов»** сделано как диапазон (мин/макс) в настройках, но пока используется только как справочное значение — на расчёты в дашборде оно не влияет (в ТЗ не было точной формулы, как именно потолок должен ограничивать план).
- **Связь «Эфир» → воронка**: количество записавшихся на разбор с экрана «Эфир» автоматически добавляется в поле «Разборы/созвоны» дневного чек-листа за дату эфира (при повторном сохранении эфира — старое значение сначала вычитается, потом добавляется новое, чтобы не было задвоения).
- **Расходы на рекламу** привязаны к календарному месяцу по дате платежа, а не к конкретному месяцу челленджа — так проще сверять с реальными счетами.
- **Дневник самопрограммирования** сохраняется по дате, история показывается на экране «Сегодня» списком (сворачивается/разворачивается по тапу), без отдельного полнотекстового поиска — с одним человеком-пользователем и вертикальной прокруткой этого достаточно.
- **Автосохранение**: все поля сохраняются в момент изменения (не только по кнопке «Сохранить») — кнопки оставлены как явное подтверждение «записано», а не единственный способ сохранить.
- Файла `mehanika-chelendzha-v1.md` в папке не было на момент сборки — все формулировки взяты из текста промпта.

## Дизайн

Тёмная тема — единственная и постоянная (без переключения по системной настройке), в духе матовой премиальной техники: графитовый фон с едва заметной текстурой, один акцентный цвет (тёмно-красный/бордовый) для кнопок и прогресса, всё остальное — оттенки серого и белого. Иконки — тонкие линейные, без заливки.
